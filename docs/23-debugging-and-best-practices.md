# 23 · 调试、代码风格与最佳实践

**学习目标**：掌握系统化的排错方法；养成良好的编码习惯；知道新手最常犯的错误。

## 1. 排错的科学方法

1. **复现**：找到稳定触发问题的最小输入。
2. **读报错**：异常类型 + 消息 + 第一个你自己的栈帧（第 13 章）。
3. **缩小范围**：二分法注释/打印，定位到哪一行开始"不对劲"。
4. **提出假设 → 验证**：变量的值是不是你以为的值？
5. **修复并写测试**，防止复发。

> 90% 的 bug 来自"我以为这个变量是 X，其实是 Y"。**打印它，或者用调试器看它。**

## 2. 使用 IDE 调试器

| 操作 | 作用 |
|------|------|
| 断点（点击行号左侧） | 程序执行到该行暂停 |
| Step Over（F8） | 执行当前行，不进入方法 |
| Step Into（F7） | 进入方法内部 |
| Step Out | 执行完当前方法返回上层 |
| Resume（F9） | 继续运行到下一个断点 |
| Watches / Evaluate | 查看、计算表达式 |
| 条件断点 | 仅当 `i == 99` 时暂停 |

在循环里排查"第 N 次才出错"时，条件断点极其好用。

## 3. 新手最常见 15 个错误

| # | 错误 | 正确做法 |
|---|------|----------|
| 1 | 用 `==` 比较字符串/包装类 | `equals` |
| 2 | 整数除法 `1/2` 得 0 | 至少一个操作数是 `double` |
| 3 | `nextInt()` 后 `nextLine()` 读到空串 | 多读一次，或统一用 `nextLine` |
| 4 | 数组/集合下标越界（差一错误） | `i < length` |
| 5 | 对 `null` 调方法 → NPE | 先判空 / `Optional` / `Objects.requireNonNull` |
| 6 | `catch` 里什么都不写 | 至少打印/记录日志 |
| 7 | 遍历时修改集合 | `removeIf` / Iterator |
| 8 | 循环里 `String +=` | `StringBuilder` |
| 9 | 只重写 `equals` 不重写 `hashCode` | 成对重写，或用 `record` |
| 10 | 用 `double` 算钱 | `BigDecimal` |
| 11 | 可变对象当 `HashMap` 的 key 后又修改 | key 不可变 |
| 12 | 忘记关闭资源 | try-with-resources |
| 13 | 忘记 `@Override` | 总是加上 |
| 14 | 多线程共享变量不同步 | 原子类/锁/并发容器 |
| 15 | `Thread.run()` 当成 `start()` | `start()` 才开线程 |

## 4. 代码风格

- **命名要有意义**：`int d;` ✘ → `int daysSinceLastLogin;` ✔。布尔变量用 `is/has/can` 开头。
- **方法短小**，一个方法一件事；嵌套不超过 3 层（用卫语句提前返回）。
- **不要魔法数字**：`if (status == 3)` ✘ → 常量/枚举。
- **注释说"为什么"**，代码本身说"做什么"。
- **缩进、空格统一**：交给 IDE 格式化（Google Java Style 或团队规范）。
- **不要复制粘贴**同一段逻辑 3 次以上——提取方法（DRY）。
- **变量尽量靠近使用处声明、作用域尽量小、尽量 final / 不可变**。

## 5. 面向对象设计原则（SOLID 简版）

| 原则 | 一句话 |
|------|--------|
| **S** 单一职责 | 一个类只有一个变化的理由 |
| **O** 开闭 | 对扩展开放，对修改关闭（用多态，而不是 if-else 链） |
| **L** 里氏替换 | 子类能替换父类而不破坏程序 |
| **I** 接口隔离 | 接口小而专，不强迫实现用不到的方法 |
| **D** 依赖倒置 | 依赖抽象（接口），不依赖具体实现 |

常见设计模式（先认识名字）：单例、工厂、建造者、策略、观察者（**NeoForge 的事件总线就是观察者模式**）、装饰器（IO 流）、模板方法。

## 6. 性能常识（不要过早优化）

1. 先保证**正确、清晰**，再测量，再优化热点。
2. 选对数据结构 > 微优化：`HashMap` 查找 O(1)，`ArrayList.contains` O(n)。
3. 循环里避免重复创建对象、字符串拼接、不必要的装箱。
4. I/O 用缓冲；大文件逐行处理。
5. 用工具测量：`System.nanoTime()` 粗测，JMH 精测，VisualVM / JFR 分析。

## 7. 代码自查清单

- [ ] 能解释每一行的作用吗？
- [ ] 边界输入（0、负数、空、null、超长）处理了吗？
- [ ] 会不会抛未处理的异常？错误信息有用吗？
- [ ] 资源（文件/连接/线程池）关闭了吗？
- [ ] 变量名、方法名读起来像一句话吗？
- [ ] 有没有重复代码可以提取？
- [ ] 有没有写测试或至少手动验证过？

## 8. 如何提问与求助

好问题包括：①你想做什么；②你做了什么（最小可复现代码）；③期望结果 vs 实际结果；④完整报错信息（别截一半）；⑤你已经尝试过什么。
使用 AI 助手时同样如此，并**要求它解释**而不是只要代码——理解才是目的。

## 小结

先复现、再读报错、再缩小范围；命名清晰、方法短小、不重复；测量后再优化。
